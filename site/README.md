# Сайт HH-Auto-Response

Лендинг и несколько служебных страниц. Живёт в своей папке и никак не связан с приложением: в сборку
PyInstaller и Docker-образ не попадает, зависимостей с ним не делит. Адрес:
<https://blazestudio.github.io/HH-Auto-Response/>.

Стек: [Astro](https://astro.build) и Tailwind CSS. На выходе обычный статический HTML без фреймворка в браузере,
весь JavaScript собирается в один небольшой файл.

## Запуск

Нужен Node.js 22.23.4 или новее.

```bash
npm install
```

```bash
npm run dev
```

Сайт откроется на <http://localhost:4321>. Проверить продакшен-сборку:

```bash
npm run build
```

```bash
npm run preview
```

## Публикация на GitHub Pages

Один раз включите её в репозитории: **Settings → Pages → Source → GitHub Actions**. Дальше всё делает
[`pages.yml`](../.github/workflows/pages.yml). Сайт публикуется, когда папка `site/` меняется в ветке `main`, после
сборки нового релиза приложения и по кнопке **Run workflow** на вкладке Actions.

Переменные сборки workflow подставляет сам:

| Переменная | Зачем |
|---|---|
| `SITE_URL` | адрес сайта для canonical, Open Graph и sitemap |
| `BASE_PATH` | подпапка сайта, сейчас `/HH-Auto-Response`. Локально её нет, сайт открывается от корня |
| `GITHUB_TOKEN` | снимает лимит GitHub API при сборке. Без него версия и звёзды тоже обычно подтягиваются |

Сборка с подпапкой локально, в PowerShell (Git Bash на Windows портит такой путь):

```powershell
$env:BASE_PATH = '/HH-Auto-Response'; npm run build
```

Свой домен подключается в **Settings → Pages → Custom domain**. Подпапка при этом исчезнет сама, менять код не нужно.

GitHub Pages не даёт задать заголовки ответа, поэтому политика безопасности и `referrer` описаны через `meta` в
`src/layouts/Base.astro`. Запрет встраивать сайт в чужие страницы так задать нельзя.

Аудитория сайта в России, поэтому после публикации стоит открыть его из российской сети без VPN. Шрифты и файлы лежат на
самом сайте, внешних CDN нет. Архивы приложения и запрос версии идут к GitHub.

## Что где лежит

| Путь | Что внутри |
|---|---|
| `src/config.ts` | ссылки, контакты, имена файлов релиза. Первое место для правок |
| `src/pages/` | страницы: `index`, `safety`, `contacts`, `404`. Новый файл здесь сразу становится страницей |
| `src/components/` | секции главной, по одному файлу на секцию |
| `src/scripts/` | вкладки, демо-окно, блок анализа, грани по краям, плавная прокрутка и боковая навигация, версия и звёзды с GitHub |
| `src/styles/global.css` | цвета, шрифты и общие классы |
| `src/assets/shots/` | снимки экрана. Копии из `docs/screenshots/dark`, Astro сам сожмёт их в WebP |
| `public/` | файлы как есть: иконки, `og.png` |

Цвета на сайте значат то же, что в журнале приложения: голубой это действие на hh, фиолетовый это нейросеть, зелёный
это готово, янтарный это пропуск.

## Важные мелочи

- Сайт лежит в подпапке, поэтому внутренние ссылки и файлы из `public/` пишите через `sitePath('/contacts')` из
  `config.ts`. Просто `/contacts` на GitHub Pages поведёт мимо сайта.
- Новая версия приложения не требует правок сайта. Ссылки на скачивание и номер версии берутся с GitHub при сборке,
  а потом обновляются в браузере. `fallbackVersion` в `config.ts` нужен, только если GitHub недоступен.
- Имена архивов заданы в `assetSuffix` в `config.ts`. Если они поменяются в `.github/workflows/build.yml`, поправьте и там.
- В корневом `.gitignore` есть правила `data/`, `logs/`, `build/`, `dist/`. Они действуют и здесь, поэтому не называйте
  так папки с исходниками сайта.

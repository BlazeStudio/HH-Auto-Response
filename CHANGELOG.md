# Changelog

Все заметные изменения HH-Auto-Response в хронологии

## 1.1.1-beta — не выпущена

### Исправлено

- Тёмная тема: в левом верхнем углу страниц «Отклики» и «Чаты» (над заголовком) светилась белая точка —
  спрятанная страница «Настройки», которую Windows показывала размером 1×1, когда программа заранее
  открывала в ней последнюю вкладку.

## 1.1.0-beta — 2026-10-31

Новое оформление — светлая и тёмная темы. «Остановить» сразу после «Запустить» больше не подвешивает
программу. Чаты: обрабатываются все непрочитанные, а не только первая порция списка, и «Робот-рекрутер»
получает ответы на все вопросы анкеты. Запуск и вкладка «Статистика» — быстрее.

### Исправлено

- Собранная программа не запускалась (окно не появлялось), если её папка лежит очень глубоко: путь к шрифту
  customtkinter внутри неё длиннее 260 символов, Windows такой шрифт не открывает, а предупреждение об этом
  customtkinter пишет в консоль, которой у программы нет. Теперь шрифты в этом случае загружаются из копии
  во временной папке — и скругления кнопок и полей рисуются так же чётко, как обычно.
- «Запустить» и сразу «Остановить»: браузер не закрывался, программа «висела» до минуты, а то и заканчивала
  работу ошибкой «hh.ru не открывается… VPN». Шаги запуска (открыть браузер, проверить доступ к hh, вход)
  посередине не прерываются, а после каждого программа шла дальше — до первой паузы уже в работе. Теперь
  «Остановить» проверяется между шагами; пока работа не началась, браузер закрывается через секунду (во время
  работы — как раньше, через 6 с), а если он ещё только запускается и окна у него нет — завершаются его
  процессы, в том числе появившиеся уже после нажатия. Остановка во время запуска — «Остановлено», а не
  ошибка. После «Остановить» фоновая проверка (подъём резюме, приглашения) 5 минут не открывает браузер сама.
- Ваш собственный Chrome, открытый из программы по ссылке (например, «Открыть чаты»), когда Chrome не был
  запущен, программа могла принять за свой браузер: спрятать его окно за край экрана, закрыть по
  «Остановить» или завершить после работы. Теперь своим считается только браузер, запущенный драйвером
  Playwright.
- Окно-сообщение появлялось, на долю секунды пропадало и появлялось снова, а мини-окно мигало при каждой
  смене темы (и при открытом сообщении — оно тоже). customtkinter перекрашивает заголовок окна, пряча его
  и показывая заново: при смене темы и сразу после появления окна. Теперь у видимого окна перерисовывается
  только рамка — как давно у главного окна.
- Чаты: обрабатывалась только первая порция непрочитанных. Список чатов hh догружает следующую, когда его
  докрутили до конца, — не сразу, а программа в этот момент решала, что чатов больше нет. Теперь догрузка
  ждётся до 3 с. В конце короткий список непрочитанных проходится ещё раз с начала: чаты, пришедшие во время
  работы, появляются сверху.
- Чаты: «Робот-рекрутер» получал ответы не на все вопросы. Отметку «Прочитано» под нашим ответом программа
  принимала за новое сообщение, видела последним свой ответ и уходила из чата, а следующий вопрос оставался
  без ответа; короткий вопрос («Ваш город?») принимался за подписи под ответом. Если робот отвечал позже, чем
  программа его ждала (`[ai] reply_wait`), в чат больше не возвращались. Теперь подписи новым сообщением
  не считаются, короткий вопрос узнаётся по «?», несколько сообщений подряд ждутся целиком, а в чат, где
  робот ответил позже, программа возвращается в этом же запуске.
- Чаты: сразу после щелчка по чату панель ещё могла показывать прошлую переписку, и нейросеть отвечала по ней.
  Теперь программа ждёт, пока откроется именно этот чат (его вакансия в шапке) и сообщения догрузятся.
- Чаты: если строка чата пропадала из списка (пришёл новый чат, hh перерисовал список), чат через 20 с
  ожидания записывался ошибкой, а после ошибки в узкой вёрстке программа не возвращалась к списку и
  заканчивала работу. Теперь список собирается заново, а к списку программа возвращается и после ошибки.
- Чаты: после включения «Только непрочитанные» программа ждёт, пока список перезагрузится, — прочитанные
  чаты из старого списка не принимаются за непрочитанные. В списке «ждут вашего ответа» чат — один раз,
  даже если в него возвращались.

### Изменено

- Новое оформление окна в светлой и тёмной теме. Светлая — серый фон и белые карточки, тёмная — почти
  чёрный фон и графитовые карточки. Меню слева — отдельная скруглённая панель, выбранный пункт выделен
  синим. Кнопки — «капсулы»: «Начать» синяя, «Остановить» мягко-красная, остальные серые. Переключатели
  («Что делать», период статистики, вкладки настроек, оформление) — серая дорожка со светлым выбранным
  вариантом. Флажки, поля, переключатели и меню — в тех же цветах. Цвета, на которых лежит белый текст,
  подобраны отдельно, чтобы текст читался и в тёмной теме.
- Страница «Отклики»: кнопки запуска — рядом с заголовком. Крупная карточка «Сегодня» — сколько откликов
  из суточного лимита hh (полоса из отрезков), какая вакансия сейчас, последний запуск и всего. Рядом
  четыре числа: с письмом, пропущено, ошибок (красное, только когда они есть) и «Этот запуск» с полосой
  прогресса. Поиск и параметры запуска — одной карточкой.
- «Оформление» в меню слева — переключатель «Авто / Светлая / Тёмная» вместо выпадающего списка.
- Запуск быстрее на несколько секунд. Проверке доступа к hh хватает ответа сервера — тяжёлая главная
  страница hh (2–7 с) больше не дорисовывается целиком; список резюме и страница резюме не открываются
  второй раз подряд (после входа и для нейросети). Переходы на них — с повтором, если hh перебил их своим
  переходом (`net::ERR_ABORTED`).
- После вакансии, на которой ничего не нажимали (hh увёз её на другую страницу, кнопки «Откликнуться» уже
  нет), пауза 6–15 с перед следующей не ждётся.
- Вкладка «Статистика» открывается без пересчёта, если с прошлого раза данные и настройки не менялись.
- «Остановить» срабатывает сразу и пока догружаются карточки выдачи (раньше — до 12 с).
- Код разложен по папкам: вместо 35 файлов подряд в `hh_auto/` — `core/` (настройки, журнал, остановка),
  `web/` (браузер и вход), `hh/` (выдача, отклики, чаты, резюме), `ai/`, `reports/` (итоги, Excel,
  статистика) и `ui/` (окно). Для пользователя ничего не меняется; схема — в README, «Что где лежит».

## 1.0.12-beta — 2026-10-26

Чаты: можно только прочитать отказы, не трогая остальное. Письмо прикладывается и там, где оно
необязательное. Обновление без пустого окна «tk» и сообщения об ошибке; подпись на кнопке обновления
помещается целиком.

### Добавлено

- Режим чатов «Только прочитать отказы» (`[chats] mode = "rejections"`, переключатель «Что делать» на странице
  «Чаты»): программа открывает только непрочитанные отказы, чтобы hh отметил их прочитанными, а остальные чаты
  не трогает — даже с включёнными ИИ-ответами (нейросеть и резюме при этом не загружаются). Такие чаты
  остаются непрочитанными и видны списком «ждут вашего ответа». Кнопка запуска в этом режиме — «Прочитать
  отказы». Выбор сохраняется в config.toml сразу, его же берут чаты по расписанию и Docker; в консоли —
  `scripts/chats.py --only-rejections`. Режим по умолчанию — «Отказы и ответы ИИ», как раньше.

### Исправлено

- Если сопроводительное письмо в вакансии необязательное, отклик уходил без письма, даже когда письма
  включены ([#7](https://github.com/BlazeStudio/HH-Auto-Response/issues/7)). В таком окне отклика hh прячет
  поле письма за кнопкой «Добавить сопроводительное», а программа искала только само поле и писала «в окне
  нет поля для письма — откликаюсь без него». Теперь она нажимает эту кнопку (ищет её и по `data-qa`,
  и по тексту), пишет письмо так же, как обычно (кнопкой hh, нейросетью или шаблоном), и, если письмо
  открылось отдельным окном, нажимает «Сохранить». Не получилось написать — письмо необязательное, поэтому
  отклик уходит без него, как раньше, а не пропускается. С выключенными письмами (`[letter] mode = "none"`)
  кнопка не нажимается. Если в окне нет ни поля, ни кнопки, программа один раз за запуск сохраняет снимок
  страницы (`logs/snapshots`) — по нему можно поправить, если hh снова поменяет вёрстку.

- «Не получилось проверить обновления: HTTP Error 403: rate limit exceeded», а при запуске окно с новой версией
  не появлялось. Без входа GitHub отвечает на вопрос «какие есть релизы» не больше 60 раз в час с одного адреса,
  и лимит общий для всех программ на компьютере и в сети. Теперь программа запоминает ответ вместе с меткой
  ETag (`data/update_check.json`) и при следующей проверке спрашивает «изменилось ли?» — ответ «нет» GitHub
  в лимит не засчитывает. Если лимит всё же исчерпан, версия берётся из ленты релизов (`releases.atom`,
  обычная страница сайта, под этот лимит не попадает): файлы релиза названы предсказуемо, и программа
  проверяет, что они уже выложены, прежде чем предлагать обновление. Не открылась и лента — понятное сообщение
  вместо «HTTP Error 403», а автоматическая проверка повторится через час, а не через 12.

- После «Перезапустить и обновить» старая версия показывала «can't invoke "winfo" command: application has
  been destroyed» и оставляла пустое окно «tk». Сообщению об ошибке было не над чем появиться — окно программы
  уже закрылось, — и для него молча создавалось новое главное окно. Пока его не закрыть руками, старая версия
  не завершалась, и программа обновления ждала её («Жду, пока закроется старая версия…»). Саму ошибку
  исправили в 1.0.11, а теперь и любая другая после закрытия окна только записывается в `logs/crash.log`;
  сообщение без главного окна показывается над своим невидимым окном, которое закрывается вместе с ним.
  Как и прежние исправления обновления, это работает начиная с обновлений с этой версии: при переходе
  с 1.0.10 на 1.0.11 сообщение и окно «tk» ещё появлялись — их можно просто закрыть.
- Кнопка обновления в меню слева: «Обновить до 1.0.11-beta» и «Перезапустить и обновить» не помещались
  и обрезались с обеих сторон. Теперь подпись подбирается под ширину меню: «Обновить до 1.0.12», а после
  скачивания — «Обновить сейчас».

## 1.0.11-beta — 2026-10-23

Резюме само поднимается в поиске каждые 4 часа. Отклики не уходят впустую: отбор по данным hh, уровень,
тесты. Приглашения — сразу, «компании мечты» — первыми, на «Статистике» — воронка и советы к резюме.
После обновления больше нет сообщения об ошибке.

### Добавлено

- Отбор вакансий по данным hh («Настройки» → «Отбор», `[quality]`). Вместе со страницей выдачи hh отдаёт
  данные о каждой вакансии (состояние страницы `HH-Lux-InitialState`), программа читает их без лишних
  переходов и пропускает: вакансии, о которых hh предупреждает (вводит в заблуждение, передаёт персональные
  данные), неподтверждённых работодателей и тех, кто на проверке (`skip_suspicious`, включено); просьбы
  писать в Telegram/WhatsApp и ссылки t.me, wa.me (`skip_messengers`, включено; вакансии про Telegram-ботов
  не трогаются); работодателей с частыми жалобами (`skip_complaints`, выключено — бывает и у крупных);
  «вечные» вакансии, созданные больше `max_age_days` дней назад (90); переполненные — больше
  `max_responses` откликов (выключено); с рейтингом ниже `min_rating` (выключено). Проверено на 450
  вакансиях из настоящих страниц hh: данные читаются все и совпадают с самой страницей. Нет данных — отбор
  не срабатывает, отклики идут как раньше. На «Статистике» — новый вид пропуска «Отсеяны: работодатель
  и вакансия».
- Уровень вакансии (`[filters] levels`): Стажёр, Junior, Middle, Senior, Lead. Пропускается вакансия, в
  названии которой явно указан другой уровень; без уровня в названии отклик будет.
- Тесты и вопросы при отклике: `[questions] skip_tests` пропускает анкеты с вариантами ответа,
  `skip_all` — любые вопросы работодателя, причём такие вакансии видно ещё в выдаче — без клика.
- Приглашения: «Собеседование», «Приглашение на собеседование» и т.п. в чатах — строка «★ Приглашение: …»
  в меню слева (щелчок откроет чаты hh) и уведомление на компьютер или в Telegram (`[notify] invitations`).
  О каждом — один раз и только о непрочитанном: старые приглашения уведомлений не вызывают.
- Фоновая проверка (`[watch]`, «Настройки» → «Расписание»): пока приложение открыто, раз в `every_minutes`
  минут (не чаще 15) браузер на минуту открывается в фоне и смотрит непрочитанные чаты, не открывая их,
  — пришло ли приглашение. Подъём резюме и «компании мечты» идут в той же проверке. «Проверить сейчас»
  и подпись, когда была прошлая проверка. Консоль — `scripts/watch.py` (например, каждые 15–30 минут:
  ничего не пора — без браузера и без файла лога); Docker делает это сам каждые 15 минут.
- «Компании мечты» (`[dream]`): ссылки на страницы компаний hh. Их свежие вакансии (ваш поиск, только эта
  компания, за 3 дня, новые сверху) проверяются при каждой фоновой проверке, и отклик уходит сразу —
  с теми же фильтрами, письмом и анкетами, не больше `max_per_check` за раз.
- Воронка на «Статистике» (`[stats] funnel`): что стало с откликами за период — приглашения, отказы и без
  ответа, по каждому запросу, виду письма и совпадению по навыкам. Статусы — из чатов hh; раз в сутки при
  чтении чатов просматриваются и прочитанные. Для этого к каждому отклику в `data/responses.jsonl`
  записываются поиск, вид письма и «подходит по навыкам» от hh.
- Советы к резюме на «Статистике» (`[stats] skill_tips`): ключевые навыки, которые чаще всего просят в вашей
  выдаче, есть ли они в резюме, и средний процент «подходит по навыкам». Текст резюме обновляется раз
  в 3 дня при откликах; хранятся только навыки и числа (`data/skills.json`).

- Поднятие резюме в поиске каждые 4 часа (`[raising]`, «Настройки» → «Расписание» → «Поднятие резюме»).
  Бесплатно, как кнопка «Поднять в поиске» на странице «Мои резюме»: программа отправляет hh тот же запрос
  с той же страницы, в вашем браузере и под вашим входом — логин и пароль не нужны. Пока приложение открыто
  (можно свернуть), браузер раз в 4 часа на несколько секунд открывается в фоне; если в это время идут
  отклики или чаты, резюме поднимается в их начале. Когда поднималось и когда снова можно — в
  `data/raising.json`, поэтому hh раньше срока не трогается; если hh ответил «ещё рано» (вы подняли вручную),
  время берётся из карточки резюме. Поднимается резюме из ссылки поиска или «Ссылки на резюме», а с
  `all_resumes = true` — все. В меню слева видно, когда следующий подъём, в настройках — когда был прошлый;
  «Поднять сейчас» — вручную. Если входа в hh нет, фоновый подъём не показывает окно входа, а пишет об этом
  в меню и пробует снова через полчаса. Для сервера — `scripts/raise_resume.py` (Планировщик заданий или cron,
  хоть каждый час: раньше срока браузер не открывается и лог не пишется); в Docker цикл проверяет это сам
  раз в час, вручную — `docker compose run --rm hh raise --force`. В «Журналах» такие запуски подписаны
  «Подъём», хранятся последние 30.

### Исправлено

- После «Перезапустить и обновить» появлялось «В окне программы произошла ошибка: can't invoke "winfo"
  command: application has been destroyed», хотя обновление проходило. Окно программы закрывалось прямо
  в обработчике событий, а тот продолжал обращаться к уже закрытому окну. Теперь после закрытия он сразу
  останавливается. Исправление работает в обновлениях начиная с этой версии: при переходе на неё
  сообщение может появиться последний раз — на обновление оно не влияет, просто закройте его.
- Если мини-окно пропадало в первые секунды после запуска программы, оно могло молча пересоздаться
  невидимым — и программа оставалась без окна на экране. Теперь в этом случае возвращается окно программы.

### Изменено

  - настройки разбиты на вкладки «Поиск · Фильтры hh · Отклики · Нейросеть · Уведомления · Прочее»: на
    экране только одна, это 70–140 окон вместо 915. Последняя открытая вкладка запоминается, а при ошибке
    в поле открывается его вкладка;
  - подписи и подсказки — обычный текст (одно окно вместо трёх), рамки строк — одно окно вместо двух;
  - флажки фильтров hh стали «чипами»: вся группа — одна картинка, выбранное синее с галочкой;
  - список логов в «Журналах» — одно окно на весь список вместо кнопки на каждый лог (до 600 окон, и все
    пересоздавались при каждом открытии страницы и после удаления);
  - окно выбора специализаций и отраслей — тоже на «чипах»: 160–175 окон вместо 800–1300;
  - на время смены страницы, вкладки и сдвига прокрутки окно замораживается и перерисовывается целиком:
    Windows не показывает промежуточных кусков и не копирует старую картинку на новое место;
  - ползунок полосы прокрутки идёт тем же путём, что и колесо мыши (раньше его исправление не касалось).
  Переход на «Настройки» — 135 мс вместо 540, на «Журналы» — 30 мс вместо 140.
- На кнопке «Обновить до …» вместо значка был пустой квадрат: «⬇» есть не в каждом шрифте. Значки на кнопке
  («скачать», «перезапустить») теперь рисует сама программа, а под кнопкой видна полоска загрузки.
- Окно установки обновления было голым окном tkinter с его иконкой-пером. Теперь оно в стиле приложения:
  иконка программы, версия, что сейчас происходит, полоса прогресса; ошибка — понятным окном.
- Остатки прошлого обновления (`_internal.old-…`) удаляются и при длинном пути к программе: эти папки на
  15 символов длиннее настоящих и упирались в ограничение Windows в 260 символов.

### Добавлено

  крупный заголовок и пояснение, кнопки с понятными подписями («Удалить все», «Выйти из аккаунта»,

## 1.0.5-beta — 2026-10-18

Эта версия — по итогам недели боевых запусков: в логах за 12–17 октября почти все остановки были не из-за
hh, а из-за самой программы. Капча, пересортированная выдача и медленный hh больше не обрывают запуск,
а анкеты реже пропускаются зря.

### Исправлено

- Капча посреди откликов останавливала программу. После 10–15 откликов подряд hh показывает окно «Пройдите
  капчу» прямо вместо отклика, а программа его не замечала: считала вакансию ошибкой («ничего не появилось»,
  «форма не закрылась»), шла к следующей, снова упиралась в капчу и через 5 таких «ошибок» останавливалась.
  Теперь программа замечает капчу после каждого нажатия «Откликнуться» и «Отправить», выводит окно браузера
  вперёд, пишет в журнал и в меню слева «Нужна капча» и, если вы разрешили уведомления, присылает
  уведомление. Дальше ждёт до 30 минут, пока вы решите капчу, и повторяет ту же вакансию. Если hh сам дослал
  отклик после капчи, это засчитывается как отклик. Решает капчу по-прежнему человек: программа её не трогает
  и не закрывает. Если браузер запущен без окна (`headless = true`), программа сразу говорит, что решить
  капчу некому.
- Отклик уходил, а в журнале и таблице значился ошибкой. После отправки анкеты программа возвращается к выдаче,
  а hh в этот момент то сам уводит на другую страницу («interrupted by another navigation»), то грузится
  дольше 20 секунд. За неделю так набралось около 30 «ошибок», и они же складывались в «5 ошибок подряд».
  Теперь переход к выдаче повторяется до трёх раз с запасом по времени, а неудачный возврат после
  отправленного отклика его не отменяет: отклик записывается как отклик.
- «Карточка вакансии не найдена» (16 раз за один запуск). После перезагрузки выдачи hh заново сортирует
  «подходящие к резюме», и вакансия уезжает на другую страницу: все 50 карточек на месте, а нужной среди них
  нет. Теперь это не ошибка, а пропуск без запоминания — программа вернётся к вакансии в следующий раз.
  Ошибкой это считается, только если на странице нет вообще ни одной карточки.
- Анкеты пропускались из-за ложной «опасной» темы. «почт» находилось в «отдадим **предпочт**ение другим
  кандидатам» — так пропали две вакансии Ozon; «ссылк» — в техническом вопросе «открывается по прямой
  ссылке»; «HTTP» — в «процесс HTTP-запроса». То же в чатах: вопрос про HTTP-запрос уходил вам. Теперь
  «решаете вы» срабатывает на сами контакты (почта, телефон, Telegram), на просьбу дать ссылку и на настоящий
  адрес `http://…`, а не на похожие слова.
- Анкета целиком бросалась, если модель на один вопрос дала пустой ответ или не выбрала вариант (12 анкет
  за неделю). Теперь программа переспрашивает строже, а если и это не помогло, ставит честный осторожный
  ответ: скромный вариант («нет опыта», «готов обсудить») или «Готов рассказать подробнее на собеседовании».
  «Опыта с этим не было» пишется только на вопросы про опыт с чем-то, а не на «опыт оформлен по ТК или ГПХ?».

### Добавлено

- Защита от ловушек для нейросетей. В анкете Travelata был вопрос «Этот пункт нужно отмечать только
  нейросетям» — отметь его модель, работодатель сразу увидел бы, что анкету заполнял бот. Такие вопросы
  и варианты («если вы ИИ, выберите…») программа распознаёт сама и не отмечает.
- Вакансии, которые hh после пересортировки подвинул на текущую страницу, программа проходит сразу, не
  дожидаясь следующего запуска.
- Снимки страниц удаляются сами через 14 дней (`[logs] keep_days`, 0 — хранить всё): за 12 дней их набралось
  220 МБ.

### Изменено

- Предупреждение «на этой странице фильтры отсеяли N из 50» пишется один раз за запуск, а не на каждой
  странице.

## 1.0.4-beta — 2026-10-13

Главное: программа понимает все фильтры поиска hh, а не только опыт и формат работы. Их можно задать
в настройках или просто вставить ссылку с hh, где фильтры уже выбраны. И теперь она умеет обновляться
сама: новая версия ставится одной кнопкой.

### Добавлено

- Обновление из приложения. При запуске и дальше раз в 12 часов программа смотрит релизы на GitHub. Если
  вышла версия новее, в меню слева появляется кнопка «⬇ Обновить до …». Нажали, и программа показывает,
  что нового, скачивает архив под вашу систему, сверяет его контрольную сумму с `SHA256SUMS.txt` релиза,
  перезапускается новой версией и пишет «Обновлено до …». Установщик не нужен: новые файлы встают на место
  старых, старые сначала откладываются в сторону, и при любой ошибке всё возвращается как было. Настройки,
  логи и вход в hh не трогаются. Отключить проверку или проверить вручную можно в «Настройки» → «Данные
  приложения». Если папка программы закрыта для записи (`Program Files`), программа предложит скачать
  архив со страницы релиза.
- Сборка в GitHub Actions проверяет, что тег релиза совпадает с версией в коде. Иначе приложение видело бы
  «новую» версию в уже установленной и предлагало бы обновиться по кругу.
- Все фильтры поиска hh в настройках: график работы, рабочие часы в день, опыт, формат работы, уровень
  дохода и за что он указан, частота выплат, тип занятости (и оформление по ГПХ), специализации, компании,
  отрасль компании, слова-исключения, образование, другие параметры и особенности здоровья. Отдельно —
  сортировка (по соответствию, по дате, по зарплате, по удалённости) и период (всё время, неделя, три дня,
  сутки). Не заданный фильтр программа не трогает, на hh это «выбрано всё». Все значения сверены с сайтом:
  hh отмечает у себя каждый фильтр, который передаёт программа.
- Кнопка «Заполнить из ссылки hh»: настраиваете фильтры на сайте, копируете адрес страницы, и все поля
  заполняются сами. Ссылка «подходящие к резюме» при этом становится ссылкой поиска, уже без фильтров.
- Специализации (194) и отрасли с подотраслями (326) выбираются по названию в отдельном окне с поиском,
  а не номерами.
- Новый фильтр программы «Откликаться только в компании, в названии которых есть…» (`include_company_words`).
  Пусто — проверка не делается.
- В журнале перед стартом видно, какие фильтры ушли на hh.
- Ollama на другом компьютере: гайд [docs/ollama.md](docs/ollama.md) с командами установки qwen3:8b на Linux,

- В настройках появилось поле «Сколько ждать ответа нейросети» (`[ai] timeout`).
- Кнопки быстрого ответа в чатах: если под сообщением есть варианты («Да» / «Нет», «Интересно», ответ

### Исправлено

- В чатах программа пропускала вопросы. Новые боты hh («ИИ-помощник», «ассистент рекрутера на базе AI»)
  считались живыми людьми, а модели показывали только последнее сообщение, поэтому из нескольких вопросов
  подряд отвечала она на один. Теперь программа отвечает всем, и ботам, и рекрутерам, на каждый вопрос.
  Пропускает только приглашения на встречу, собеседование или звонок (время согласуете вы), а также
  просьбы о документах, контактах и деньгах.
- В чатах ответы иногда были невпопад: на вопрос Светланы про Docker Swarm ушло «Да, готов.», на сообщение
  hh «Ответьте на приглашение» — «Предпочитаю гибкий формат работы». Модель брала старые вопросы бота из
  начала переписки. Теперь программа проверяет, что вопрос взят из новых сообщений, а ответ по сути
  (короткое «Да, готов» на открытый вопрос не пройдёт, остальное проверяет сама модель отдельным запросом).
  Не по сути — переспрашивает, снова мимо — оставляет чат вам. Нет новых вопросов — ничего не пишет.
- Срок выхода и зарплату в чатах программа, как и в анкетах, берёт только из вашего контекста: модель
  отвечала «в ближайшие 2 недели», хотя об этом нигде не было сказано.
- В ответах в чатах больше нет «в резюме не указано» и выдуманных технологий (в одном ответе всплыли
  AWS и Google Cloud, которых в резюме нет).
- Фильтр «Только непрочитанные» снова не включался. hh завернул переключатель в две вложенные метки,
  и на медленной странице программа щёлкала раньше, чем страница оживала. Теперь она ждёт, пока список
  чатов догрузится, щёлкает только по подписи и пишет в журнал, что именно не так, если галочка не встала.
- Уведомления на Windows были подписаны «Windows PowerShell». Теперь они приходят от HH-Auto-Response
  с нашей иконкой.
- С Ollama на другом компьютере программа вела себя как с локальной: при недоступном сервере пыталась
  запустить Ollama у себя и советовала её установить, а при выходе выгружала модель на чужом сервере.
  Теперь она только проверяет связь и пишет, что проверить: сервер, сеть или SSH-туннель.
- При долгом ответе модели программа писала «Ollama не отвечает», хотя связь была. Теперь пишет, что
  модель не успела, и подсказывает увеличить время ожидания.
- «Модель qwen3:8b не скачана», хотя она скачана. Так было в двух случаях. Первый: в «Адрес API» вписан
  адрес из браузера, `http://localhost:11434` без `/v1`, и Ollama отвечала «404 page not found». Второй:
  модель в Ollama называется иначе, например `ollama run qwen3` скачивает её как `qwen3:latest`.
  Теперь адрес можно писать как угодно (`localhost:11434`, с `/v1`, хоть `…/api/tags`), а программа сверяет
  имя со списком скачанных моделей. `qwen3`, `qwen3:latest` и `qwen3:8b` находят одну и ту же модель.
  Если нужной модели нет, в ошибке перечислены те, что есть. Ошибка про неверный адрес теперь отдельная.
- Каждый запрос к Ollama на Windows шёл на 2 секунды дольше: `localhost` сначала пробует IPv6, а Ollama
  слушает только IPv4. Теперь программа обращается к `127.0.0.1`, запрос короче на 2 секунды.
- В «Настройках» при прокрутке колесом текст «плыл»: посреди прокрутки надписи и поля на мгновение
  рисовались дважды, со сдвигом. Теперь щелчки колеса применяются не чаще раза в кадр, а после каждого
  сдвига окно дорисовывается целиком. То же в окне выбора специализаций и в списке журналов.
- Прокрутка застревала, когда курсор попадал на многострочное поле (готовый текст письма, контекст для
  нейросети): customtkinter отдавал колесо полю, даже если листать в нём нечего. Теперь колесо листает поле,
  только пока в нём есть что листать, а дальше страницу.

### Изменено

- Фильтры hh переехали из `[filters]` в новый раздел `[hh_filters]`. Старые `experience` и `work_format`
  из `[filters]` подхватываются сами, конфиг править не нужно.

  - консольные скрипты — в `scripts/`: `python scripts/responses.py` вместо `python main.py`,

  - `docker-compose.yml` — в `docker/`, команды `docker compose` теперь выполняются оттуда. Данные сервера

  - заметки к релизу — в `docs/release-notes.md`;
  - `requirements-app.txt` влился в `requirements.txt`, ставится одной командой.
- Из исходников данные (`config.toml`, логи, история, вход в hh) теперь лежат в `hh-data/`, а не россыпью
  в корне проекта. Старые файлы переезжают туда сами при первом запуске.
- Версия приложения записана в одном месте, `hh_auto/__init__.py`. Оттуда её берут окно, сборка для macOS
  и проверка обновлений.

  чёткая от 16 до 1024 px. Для 16–32 px (панель задач, трей, заголовок окна) отдельный вариант
  с крупными буквами, а иконка окна ставится ровно под масштаб экрана, без растягивания.

### Добавлено

- Письмо нейросетью без подписки hh (режим «Генерировать нейросетью»). Программа читает описание
  вакансии и пишет письмо под неё по вашему резюме. В режиме «кнопкой hh» нейросеть подстрахует, если
  кнопки «Сгенерировать» нет или генерация не удалась. Проверить можно кнопкой «Тест письма».
- Журнал в окне можно копировать: кнопка «Копировать», Ctrl+C (в любой раскладке) и меню по правой
  кнопке. В «Журналах» можно удалить один лог, все логи или снимки страниц, рядом видно, сколько они весят.
- Снимки страниц при ошибках (скриншот и HTML) можно отключить: `[logs] snapshots = false`. По умолчанию
  они включены.
- Уведомление по итогам запуска: на компьютере (Windows, macOS, Linux) или в Telegram. Приложение
  один раз спрашивает разрешение, без согласия ничего не приходит.
- Сборка под macOS (`.app`) и Linux тем же `./build.sh`. Linux-версию можно собрать и из Windows
  через Docker (`./build-linux.sh`), а Mac-версию без Mac — в GitHub Actions.
- Публикуете релиз на GitHub — сборка запускается сама и прикладывает к нему архивы для Windows,
  macOS (Apple Silicon и Intel) и Linux с версией в имени и файл контрольных сумм SHA256SUMS.txt.
- Docker-образ для сервера: работает сам по кругу. Первый вход в hh делается по VNC через SSH-туннель.
  Пошаговая инструкция есть в README.
- `python main.py --login`: только войти в hh и сохранить сессию.
- Переменная `HH_AUTO_HOME` задаёт свою папку для данных.
- Рядом с версией в окне появилась ссылка на GitHub.

# Нейросеть на другом компьютере: Ollama и qwen3:8b

У меня HH-Auto-Response отвечает на анкеты через Ollama с моделью `qwen3:8b` на видеокарте RTX 3080:
ответ за 2–5 секунд, бесплатно, резюме никуда не уходит. Но видеокарта нужна не там, где запущена программа.
Модель можно поставить на любой компьютер с видеокартой — домашний ПК, сервер, второй ноутбук — а программа
будет ходить к ней по сети. Это удобно, если программа работает на слабом ноутбуке или в Docker на сервере
без видеокарты.

Ниже «сервер» — компьютер, где будет Ollama, а «ваш компьютер» — тот, где работает HH-Auto-Response.

## Что нужно серверу

| | Хорошо | Терпимо |
|---|---|---|
| Видеокарта | NVIDIA от 8 ГБ видеопамяти (RTX 3060 12 ГБ, 3070, 3080, 4060 Ti 16 ГБ…) или Mac на Apple Silicon с 16 ГБ памяти | без видеокарты, на процессоре |
| Память | 16 ГБ | 16 ГБ |
| Диск | 6 ГБ под модель | 6 ГБ |
| Скорость ответа | несколько секунд | ориентировочно от полуминуты — для анкет терпимо, просто медленнее |

Видеокарты AMD Ollama поддерживает на Linux и Windows, но я проверял только NVIDIA.

## 1. Установить Ollama на сервер

**Linux** — ставится вместе со службой, которая запускается сама:

```bash
curl -fsSL https://ollama.com/install.sh | sh
```

**Windows** — установщик с [ollama.com/download](https://ollama.com/download) или в PowerShell:

```powershell
winget install Ollama.Ollama
```

**macOS** — приложение с [ollama.com/download](https://ollama.com/download) или через Homebrew:

```bash
brew install ollama
```

**Docker** (Linux с видеокартой NVIDIA, нужен NVIDIA Container Toolkit). Порт открыт только для самого
сервера — подключаться к нему будем через SSH-туннель (вариант А ниже):

```bash
docker run -d --gpus=all --restart unless-stopped -v ollama:/root/.ollama -p 127.0.0.1:11434:11434 --name ollama ollama/ollama
```

## 2. Скачать модель

На сервере (в Docker — `docker exec ollama ollama pull qwen3:8b`):

```bash
ollama pull qwen3:8b
```

Проверить, что модель отвечает:

```bash
ollama run qwen3:8b "Ответь одним словом: работает /no_think"
```

Пока модель отвечает, в соседнем окне `ollama ps` покажет, где она работает: `100% GPU` — на видеокарте,
`100% CPU` — на процессоре (тогда проверьте драйвер видеокарты).

## 3. Подключить ваш компьютер к серверу

### Вариант А: SSH-туннель (советую)

Ollama на сервере остаётся закрытой и слушает только сам сервер, а ваш компьютер ходит к ней через
зашифрованный SSH. Ничего на сервере открывать не нужно, работает и по интернету. Нужен только SSH-доступ
к серверу (на Windows 10/11 команда `ssh` уже есть в PowerShell).

На вашем компьютере откройте туннель и оставьте окно открытым, пока работает программа:

```bash
ssh -N -L 11435:127.0.0.1:11434 user@адрес-сервера
```

Порт 11435 у вас на компьютере ведёт в Ollama на сервере. Он не 11434, чтобы не пересечься с Ollama,
если она стоит и у вас. В программе адрес будет `http://localhost:11435`.

Чтобы туннель сам переподключался после обрыва (Linux, macOS), есть `autossh`:

```bash
autossh -M 0 -N -o ServerAliveInterval=30 -L 11435:127.0.0.1:11434 user@адрес-сервера
```

### Вариант Б: по домашней сети или VPN

Если сервер и ваш компьютер в одной сети (дома, в офисе или в VPN вроде Tailscale), Ollama можно открыть
для сети. **У Ollama нет пароля**: кто достучится до порта, тот пользуется вашей видеокартой и может удалять
модели. Поэтому порт открываем только для своей сети и никогда — в интернет.

Linux (служба systemd):

```bash
sudo systemctl edit ollama
```

В открывшемся редакторе добавьте и сохраните:

```ini
[Service]
Environment="OLLAMA_HOST=0.0.0.0:11434"
```

```bash
sudo systemctl daemon-reload && sudo systemctl restart ollama
```

Пустить в порт только домашнюю сеть (если включён ufw; подставьте свою подсеть):

```bash
sudo ufw allow from 192.168.1.0/24 to any port 11434 proto tcp
```

Windows: задайте переменную, затем закройте Ollama в трее и запустите снова.

```powershell
setx OLLAMA_HOST 0.0.0.0:11434
```

Пустить в порт только локальную сеть (PowerShell от администратора):

```powershell
New-NetFirewallRule -DisplayName "Ollama" -Direction Inbound -Protocol TCP -LocalPort 11434 -RemoteAddress LocalSubnet -Action Allow
```

macOS: задайте переменную и перезапустите приложение Ollama.

```bash
launchctl setenv OLLAMA_HOST "0.0.0.0:11434"
```

Docker: в команде из шага 1 замените `-p 127.0.0.1:11434:11434` на `-p 11434:11434`.

Узнать адрес сервера в сети: на Linux `hostname -I`, на Windows `ipconfig`, на macOS
`ipconfig getifaddr en0`. В программе адрес будет вида `http://192.168.1.50:11434`.

### Проверить связь с вашего компьютера

Должна прийти версия Ollama, а во втором ответе — `qwen3:8b` в списке моделей. Для туннеля подставьте
`localhost:11435`. На Windows пишите `curl.exe`, а не `curl`.

```bash
curl http://192.168.1.50:11434/api/version
```

```bash
curl http://192.168.1.50:11434/api/tags
```

## 4. Настроить HH-Auto-Response

В приложении: «Настройки» → «ИИ-ответы в чатах»:

1. «Нейросеть» — Ollama.
2. «Модель» — `qwen3:8b` (или пусто, это модель по умолчанию).
3. «Адрес API» — `http://localhost:11435` для туннеля или `http://192.168.1.50:11434` для сети.
   `/v1` на конце можно не писать, программа допишет сама.
4. «Проверить подключение к ИИ» → должно быть «Нейросеть отвечает».
5. «Сохранить».

То же в `config.toml`:

```toml
[ai]
enabled = true
provider = "ollama"
model = "qwen3:8b"
base_url = "http://localhost:11435"  # туннель; по сети — "http://192.168.1.50:11434"
timeout = 120                        # сколько ждать ответа; на процессоре ставьте побольше
```

Когда Ollama на другом компьютере, программа её не запускает и не выгружает модель при выходе: сервером
управляет сам сервер. Сколько модель держится в памяти после ответа, задаёт там переменная
`OLLAMA_KEEP_ALIVE` (по умолчанию 5 минут).

## Ollama и HH-Auto-Response в Docker на одном сервере

Если программа уже работает на сервере в Docker ([README → Docker на сервере](../README.md#docker-на-сервере)),
Ollama проще поставить рядом в тот же `docker compose`. Создайте рядом с `docker-compose.yml` файл
`docker-compose.override.yml`:

```yaml
services:
  ollama:
    image: ollama/ollama
    restart: unless-stopped
    volumes:
      - ollama:/root/.ollama
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: all
              capabilities: [gpu]
  hh:
    depends_on: [ollama]

volumes:
  ollama:
```

Запустить и скачать модель:

```bash
docker compose up -d ollama
```

```bash
docker compose exec ollama ollama pull qwen3:8b
```

В `./hh-data/config.toml` укажите `base_url = "http://ollama:11434"`. Порт Ollama при этом наружу
вообще не открывается: программа ходит к ней внутри сети Docker. Без видеокарты уберите блок `deploy`.

## Если не работает

| Что пишет программа | Что проверить |
|---|---|
| «Ollama на … не отвечает» | Запущена ли Ollama на сервере (`ollama ps`, на Linux `systemctl status ollama`); для сети — `OLLAMA_HOST=0.0.0.0` и правило брандмауэра; адрес сервера не сменился |
| «на localhost:11435 никто не отвечает — открыт ли SSH-туннель» | Окно с `ssh -N -L …` открыто и не оборвалось |
| «в Ollama нет модели «qwen3:8b». Скачаны: …» | Если нужной модели нет в списке — `ollama pull qwen3:8b` на сервере (не на вашем компьютере). Если она есть под другим именем — впишите это имя в «Модель» как есть. `qwen3`, `qwen3:latest` и `qwen3:8b` программа сопоставляет сама |
| «по адресу … нет API нейросети (HTTP 404)» | В «Адрес API» вписан не адрес Ollama. Нужен вида `http://адрес:11434`, без лишнего в конце |
| в браузере `qwen3:8b` видна, а программа пишет, что модели нет | Браузер и программа смотрят в разные Ollama. Чаще всего так бывает, если туннель открыт на тот же порт 11434, на котором работает и своя Ollama. Сравните список «Скачаны: …» из ошибки с `http://localhost:11434/api/tags` в браузере и откройте туннель на 11435 |
| ответы очень медленные | `ollama ps`: если `CPU` вместо `GPU` — драйвер видеокарты; в Docker — `--gpus=all` |
| «нейросеть не успела ответить за … с» | Увеличьте «[ai] timeout» в настройках (на процессоре — 180 и больше) |

Модели меньше, например `qwen3:4b` (2,5 ГБ), запустятся и на слабом железе, но качество ответов
на анкетах я проверял только у `qwen3:8b` (12 из 12 на моём наборе ситуаций со страховками программы).
